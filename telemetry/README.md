# TorrFrame Analytics

TorrFrame предлагает добровольно поделиться агрегированной статистикой в мастере настройки и в блоке **Конфиденциальность** внизу страницы **Настройки → О приложении**. До явного согласия клиент не создаёт идентификатор и не отправляет запросы. Существующая установка получает одно предложение, которое можно закрыть. Предпросмотр показывает отчёт локально. До согласия поле идентификатора в предпросмотре равно `null`.

## Архитектура

`tv.torrframe.core.telemetry` владеет согласием, локальной очередью, сериализацией и отдельным HTTP-клиентом. TorrFrame сообщает модулю только типизированные признаки использования и передаёт язык и тему. Модуль не читает содержимое медиатеки, конфигурацию серверов или секреты. Состояние сохраняется атомарно в Android `noBackupFilesDir`. Debug и Release используют разные файлы и UUID. Настройки приложения должны завершить загрузку до инициализации модуля.

Первый heartbeat возможен не раньше чем через 12 секунд после открытия интерфейса. Возможность отправки проверяется каждые пять минут только при видимой Activity. Приложение отменяет отправку при уходе интерфейса в фон или отзыве согласия. Повторяемые признаки за день объединяются в одну битовую маску. Запуск Android и фоновый TorrServer не инициируют heartbeat. HTTP-клиент использует собственные таймауты, ограничение тела 2048 байт и не следует перенаправлениям. Одновременно выполняется максимум один запрос. Ошибки остаются внутри модуля.

Локальные часы определяют календарные дни UTC для отчётов. После сбоя применяется увеличивающийся интервал между попытками, максимум три попытки за локальные сутки, с учётом `Retry-After`. Состояние попытки записывается до отправки. Для промежутков используется монотонное время, когда оно применимо, и сохранённые настенные часы после перезагрузки. Сервер определяет сутки heartbeat независимо от клиента. При неверной дате система может отложить или потерять отчёт за день. Сервер всё равно принимает максимум одну запись активности за свои сутки.

**Отключение** прекращает сбор, отменяет запросы и удаляет локальный ID и очередь. Повторное согласие создаёт новый UUID. **Сброс ID** очищает очередь и выдаёт новый UUID при сохранении согласия. Отмена не отзывает уже принятые сервером запросы. Отправленные записи очищаются по сроку хранения.

Worker `torrframe-telemetry` хранит данные в отдельной D1 `torrframe-analytics`. Панель и API статистики требуют авторизации. При использовании Cloudflare Access Worker проверяет подпись, issuer, audience и срок жизни JWT. Альтернативный режим использует выделенный пароль через HTTPS. Для локального запуска применяется отдельная авторизация на loopback. Worker определяет страну только через `request.cf.country`. Cloudflare как сетевой посредник технически обрабатывает IP при соединении. TorrFrame Analytics не читает IP в Worker и не сохраняет IP, User-Agent, заголовки и исходные тела запросов. Workers Observability отключён в конфигурации.

## Поля heartbeat

| Поле | Значение |
| --- | --- |
| `schemaVersion` | Сейчас `1` |
| `installationID` | Случайный UUID v4 после согласия. Сохраняется при обновлении и удаляется при очистке данных или переустановке |
| `appVersion`, `appVersionCode` | Версия и номер сборки TorrFrame |
| `androidApiLevel` | Целое число. Панель выводит название версии Android по API Level |
| `manufacturer`, `deviceModel` | Фиксированные категории из клиентского и серверного списков, включая `Other` и `Unknown` |
| `cpuArchitecture` | ABI запущенной сборки `arm64-v8a` или `armeabi-v7a`. Разрядность берётся из процесса, а не предпочтительной архитектуры устройства |
| `ramBucket` | Диапазоны системной RAM в ГиБ `lt1`, `1to2`, `2to3`, `3to4`, `4to6`, `6to8`, `gte8`, `Unknown`. Нижние границы включены |
| `deviceType` | `Android TV`, `Other`, `Unknown` |
| `interfaceLanguage` | `ru` или `en` |
| `theme` | `light` или `dark`, состояние оформления в момент heartbeat |
| `usage.date` | Необязательный отчёт за завершённую дату UTC из последних семи суток |
| `usage.features` | Ровно двенадцать булевых полей из таблицы ниже |

| Признак | Подтверждающее действие |
| --- | --- |
| `builtinTorrServer`, `externalTorrServer` | Успешный запрос списка, деталей, добавления или удаления через соответствующий TorrServer |
| `builtinPlayer` | Media3 вошёл в состояние фактического воспроизведения |
| `externalPlayer` | Android принял запуск внешнего плеера. TorrFrame не наблюдает дальнейшее воспроизведение и не отправляет имя плеера |
| `phoneRemote` | Успешное сопряжение или ответ на авторизованный запрос состояния |
| `torrentSearch` | Хотя бы один встроенный провайдер завершил поиск |
| `jackett` | Выполнен и разобран ответ поиска Jackett |
| `tmdb`, `cub` | Из соответствующего каталога показаны данные |
| `afr` | DisplayManager подтвердил запрошенный TorrFrame режим экрана |
| `favorites`, `watchLater` | Подтверждённое изменение соответствующего списка |

Не собираются названия и ID фильмов, запросы поиска, magnet-ссылки, торрент-хеши, файлы и медиатека, история или длительность просмотра, адреса сервисов, системные и рекламные ID, MAC, IMEI, серийные номера, имена Wi‑Fi, установленные приложения, ключи и пароли, точные координаты, логи, необработанные ошибки и сетевые тела посторонних запросов. Разрешение на геолокацию не требуется.

### API и хранение

`POST /v1/heartbeat` принимает только JSON заданной формы. [Синтетический пример JSON](heartbeat.example.json). Если есть завершённый день, следующий heartbeat несёт один ожидающий отчёт. При пропусках выбирается самый старый ещё пригодный отчёт. Отсутствующее поле `usage` отличается от отчёта с двенадцатью `false`. Сервер отвечает `204` с `X-Telemetry-Day`. Если конкретная дата отчёта принята или уже учтена в replay, `X-Telemetry-Usage` разрешает убрать её из очереди. `/health` проверяет доступность Worker без обращения к D1. `/admin/api/stats` возвращает только агрегаты.

| Таблица | Назначение и срок |
| --- | --- |
| `activity` | Одна запись на пару дата/псевдоним, 90 календарных дней |
| `feature_reports` | Одна битовая маска на пару дата отчёта/псевдоним, 90 дней |
| `installations` | Первое появление и последнее подтверждение псевдонима, до 400 дней неактивности |
| `daily` | Дневное число активных и новых установок без ID, 730 дней |
| `totals` | Приблизительный счётчик установок без ID |

Триггеры в [миграции](server/migrations/0001_telemetry.sql) поддерживают дневные и общие показатели в той же транзакции, что и вставку активности. Сервер хранит только HMAC-SHA-256 с выделенным секретом. Смена секрета разрывает связь между прежними и новыми отчётами и приведёт к повторному учёту вернувшихся установок. Храните секрет вместе с отдельным планом восстановления. Возврат после очистки неактивных ID или сброс UUID тоже может увеличить оценку. DAU считается на последний выбранный день. WAU и MAU используют 7 и 30 дней до этой даты включительно. На границе 90-дневной истории неполные окна показаны прочерком. Доля версий основана на последнем отчёте каждой установки за период. Доля обновившихся использует выборку установок, у которых в этом периоде наблюдалась более ранняя сборка. Доля функций использует только установки с отчётами о функциях за период. Значения с числом установок меньше пяти группируются в «Другие». Общая категория неизвестных значений показана отдельно.

## Локальный запуск

Из `telemetry/server`:

```sh
npm ci
cp .dev.vars.example .dev.vars
# Заполнить оба поля отдельными секретами с помощью openssl rand -hex 32
npm run migrate:local
npm run dev
```

Откройте `http://127.0.0.1:8787/admin/` и используйте логин `admin` и локальный `LOCAL_ADMIN_PASSWORD`. Для смены локального пароля измените `.dev.vars` и перезапустите Worker. Синтетическое наполнение отдельной локальной D1 запускается командой `node scripts/seed-local.mjs` после миграций. Для изолированного профиля передайте одинаковый путь через `--persist-to` Wrangler и первым параметром скрипту. Панель показывает метку «Тестовое окружение».

Debug по умолчанию не делает сетевых запросов аналитики. Для интеграционного прогона задайте `TORRFRAME_TELEMETRY_DEBUG_URL=http://127.0.0.1:8787/v1/heartbeat` при сборке и пробросьте loopback с `adb reverse tcp:8787 tcp:8787`. Разрешены только литералы `127.0.0.1` и `[::1]`; адрес хоста эмулятора `10.0.2.2`, внешние DNS-имена и production endpoint отклоняются в клиенте. Согласие остаётся обязательным. Release использует отдельно заданный HTTPS URL на порте 443 с точным путём `/v1/heartbeat`. Без валидного `TORRFRAME_TELEMETRY_URL` отправка выключена.

```sh
npm run check
npm test
npm run dry-run
```

Android-проверки запускаются через `./scripts/build-local.sh :app:testDebugUnitTest :torrent-search:test`. Для реального Android TV установите тестовую сборку и запустите `connectedDebugAndroidTest` с классами `tv.torrframe.core.telemetry.TelemetryPrivacyDeviceTest` и `tv.torrframe.core.telemetry.TelemetryStorageDeviceTest`.

## Развёртывание нового production

1. В отдельном проекте Workers Free проверьте доступность квот аккаунта. Локально войдите в Wrangler и создайте **новую** D1 командой `npx wrangler d1 create torrframe-analytics`.
2. Скопируйте `wrangler.production.example.json` в игнорируемый `wrangler.production.json`. Внесите ID новой D1. Для своего домена замените `routes[0].pattern`. Для бесплатного адреса `torrframe-telemetry.<поддомен-аккаунта>.workers.dev` удалите `routes` и установите `workers_dev: true`. Сохраните имя Worker, отключённые preview URLs и Observability.
3. Выберите один способ входа в панель. Для Cloudflare Access создайте приложение Zero Trust для `/admin` и `/admin/*`. Допустите только владельца и разрешённых администраторов. Укажите домен команды в `ACCESS_ISSUER` и audience в `ACCESS_AUDIENCE`. Для входа по паролю удалите эти две переменные, задайте `ADMIN_AUTH_MODE: "password"` и добавьте `ADMIN_CREDENTIAL_SHA256` в `secrets.required`. `/v1/heartbeat` и `/health` доступны без входа в панель.
4. Создайте отдельный JSON-файл секретов с правами `0600` вне репозитория. Поле `IDENTITY_HMAC_SECRET` содержит новый случайный секрет. В режиме пароля добавьте `ADMIN_CREDENTIAL_SHA256`, рассчитанный по примеру ниже. Примените миграцию `npm run deploy -- migrate` и проверьте конфигурацию командой `npm run deploy -- dry-run /закрытый/путь/worker-secrets.json`.
5. Разверните Worker командой `npm run deploy -- publish /закрытый/путь/worker-secrets.json`. Обязательные секреты загружаются вместе с версией Worker.
6. Проверьте `/health`, отказ на `/admin/api/stats` для гостя и вход в панель. Затем проверьте приём только явно согласованного тестового heartbeat. Синтетические наборы в production не импортируйте.
7. Соберите Release с `TORRFRAME_TELEMETRY_URL=https://<выделенный-хост>/v1/heartbeat`. Установите `LATEST_BUILD` равным номеру актуальной опубликованной сборки. При изменении схемы согласуйте версии клиента и Worker, снимите резервную копию, примените миграцию, затем обновите Worker и клиент.

В режиме пароля браузер запрашивает логин `admin` и отдельный случайный пароль из 64 шестнадцатеричных символов, созданный командой `openssl rand -hex 32`. В Worker помещается только SHA-256 от строки `Basic ` и Base64-кодировки `admin:<пароль>`. Неудачные попытки с заголовком авторизации лимитируются отдельно от запросов статистики. Локальный пароль применяется только на loopback. Действующий Worker и база TorrServe-Silicon не входят в эту процедуру.

Чтобы получить хеш нового пароля, передайте его из приватного файла с одной строкой. Для смены пароля передайте результат в `npx wrangler secret put ADMIN_CREDENTIAL_SHA256 --config wrangler.production.json` через stdin и обновите локальную копию `worker-secrets.json`, если используете её при деплое. Секрет идентификаторов при этом сохраняется.

```sh
node --input-type=module -e 'import { createHash } from "node:crypto"; import { readFileSync } from "node:fs"; const p = readFileSync(0, "utf8").trim(); if (!/^[0-9a-f]{64}$/.test(p)) throw Error("Expected a 64-character hex password"); console.log(createHash("sha256").update("Basic " + Buffer.from("admin:" + p).toString("base64")).digest("hex"));' < /закрытый/путь/admin-password
```

### Бесплатные квоты, нагрузка и резервное копирование

На Workers Free Cloudflare указывает 100 000 запросов в сутки на аккаунт и 10 мс CPU на обычный запрос. D1 Free допускает 5 млн прочитанных и 100 000 записанных строк в сутки на аккаунт, до 500 МБ на базу и до 5 ГБ на аккаунт. Cron занимает один из пяти бесплатных Cron Triggers. [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/) · [D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/) · [D1 Limits](https://developers.cloudflare.com/d1/platform/limits/)

По умолчанию D1 принимает не более 1000 разных heartbeat в сутки. Разумный запас для оценки — до десяти записанных строк на принятие с учётом триггеров, новых установок, отчётов и индекса. Это порядка 10 000 строк записи в сутки плюс пакетная очистка. Cron работает четыре раза в день и за запуск удаляет до 1000 строк из каждой таблицы с истекшим сроком. Строки индекса также учитываются в записи. Суточный лимит настраивается вниз и ограничен сверху числом 2000. Повторы дают чтения для проверки идентификатора и даты, но не повторные вставки. Ограничители на весь вход, на HMAC установки и на запросы статистики действуют отдельно по Cloudflare location. Атомарный лимит приёма в D1 действует глобально.

При 1000 установок в день за 90 дней получится до 90 000 строк активности и столько же отчётов. Запрос панели за 90 дней читает эти таблицы для нескольких выборок, поэтому он расходует больше строк чтения, чем приём отдельного heartbeat. Измерьте `Rows Read`, `Rows Written` и запросы Worker по фактическим графикам до роста трафика.

Квоты одного аккаунта общие с TorrServe-Silicon. Если он достигает своего лимита в 5000 heartbeat в сутки, ориентир в 5–8 записанных строк на heartbeat с учётом триггеров, индексов и доли новых установок даёт ещё 25–40 тысяч строк. Вместе с TorrFrame это порядка 35–50 тысяч записанных строк в сутки до учёта очистки, других нагрузок аккаунта и пиков. Это оценка по схемам, фактические показатели production не измерялись. При приближении к общей квоте уменьшите `DAILY_LIMIT` и частоту обновления панели. Платные функции в конфигурацию не включены.

Перед миграциями снимайте экспорт **только** `torrframe-analytics` с помощью `npx wrangler d1 export torrframe-analytics --remote --output <закрытый-путь>`. Храните его зашифрованным и ограничьте доступ. D1 Free предоставляет Time Travel на семь дней. Для диагностики восстановления сначала проверьте процедуру на отдельной тестовой базе, затем используйте Time Travel или импорт экспорта в выделенную D1 и переключите binding только после проверки агрегатов. Не помещайте экспорты и HMAC-секрет в Git. Срок хранения экспортов должен учитывать срок хранения исходных записей. [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)
