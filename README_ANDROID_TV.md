# TorrFrame — Android TV

Самостоятельное нативное приложение для Android TV, Kotlin и Compose for TV.
Исходники приложения находятся в `android-tv/`.

Новый раздел настроек TorrServer: [возможности, API и проверки](docs/android-tv-torrserver-settings.md).

## Название и идентификатор приложения

Название приложения на всех языках — **TorrFrame**. Идентификатор Android APK,
пространство имён исходников и тестов — `tv.torrframe`.
Плитка Android TV напрямую открывает `tv.torrframe.MainActivity`.

Сборка с новым идентификатором устанавливается как новое приложение. При переходе
с прежних сборок требуется удалить старую установку; её настройки и локальные
данные автоматически не переносятся. Последующие обновления TorrFrame с тем же
идентификатором и подписью сохраняют данные обычным образом.

## Быстрый запуск

Откройте каталог **android-tv** в Android Studio. APK для проверки лежит в
`artifacts/TorrFrame-TV-debug.apk`.
Нужны Android 8.0+ (API 26+) и ARM64 либо ARMv7. x86 не включён.
При первой установке выбран русский язык, Phone Remote включён, нижние подсказки
по навигации скрыты. Сохранённые пользователем настройки при обновлении сохраняются.
В ручных командах ниже замените IP:PORT адресом приставки. Для повседневной
разработки используйте автоматическую отправку через VS Code, описанную ниже.

```sh
.tools/sdk/platform-tools/adb -s IP:PORT install -r artifacts/TorrFrame-TV-debug.apk
.tools/sdk/platform-tools/adb -s IP:PORT shell am start -n tv.torrframe/.MainActivity
```

Preview APK собран с R8 и сокращением ресурсов, но подписан **локальным debug-ключом**.
Он подходит для установки и проверки, не является подписанным публичным релизом.
Debug и preview на этом компьютере используют один сертификат и заменяют друг друга.

TorrServer MatriX.146.1 уже включён в APK. Отдельно устанавливать сервер не нужно.
Он автоматически запускается при открытии приложения. Библиотека и настройки
сохраняются на устройстве. По умолчанию включён доступ из локальной сети:
классический веб-интерфейс доступен в браузере по `http://IP_ПРИСТАВКИ:8090`.
Точный адрес показан в настройках TorrServer и обновляется при смене IP или порта.
Для этого не нужен ADB или включённый Phone Remote. Приложение и плеер продолжают
подключаться к серверу через локальный адрес.

Сетевой режим поддерживает сервер foreground-службой после выхода из приложения,
независимо от автозапуска при включении приставки. Сетевой доступ можно отключить:
сервер будет слушать только loopback. Когда отключены и сеть, и автозапуск,
сервер без активного плеера останавливается после короткой задержки в фоне.
В настройках также можно выбрать внешний HTTP/HTTPS TorrServer вместо встроенного.

Добавление фильмов выполняется через поиск Jackett. Ручной ввод magnet-ссылок
в интерфейсе отсутствует.

В **Настройки → Оформление → Масштаб интерфейса** кнопки «−» и «+» меняют
масштаб от 70 до 110% с шагом 5%. По умолчанию — 85%; отдельная кнопка возвращает
это значение. Масштаб применяется сразу и сохраняется автоматически, без кнопки
«Сохранить». Меняются размеры текста, кнопок, отступов и карточек; сетка адаптируется
к доступному месту. Верхняя панель и нижние подсказки стали компактнее, кнопка
телефонного пульта находится в верхней панели. Параметр также применяется к
контролам плеера при его открытии, без изменения размера видеоповерхности.

В этом же блоке доступны язык, светлая/тёмная тема и включение всей нижней панели
подсказок вместе с надписью Android TV. При отключении убирается и нижний отступ.
Изменения общих настроек сохраняются автоматически; отдельной кнопки Save нет.
Акцент по умолчанию — `#008800`; также доступны белый, `#FF8A3D`, `#F472B6`
и `#3B82F6`. Поля ввода при фокусе сохраняют размер и внутреннюю рамку.
Последний блок настроек — «О приложении».
В шапке две вкладки: поиск и библиотека. При запуске открывается библиотека.
Вкладка Catalog / «Каталог» открывает каталог TMDB: шесть подборок, поиск фильмов и сериалов
и подробные информационные страницы. Jackett остаётся в настройках и коде,
но новый каталог его не вызывает. Архитектура, кеш и проверки описаны
в [docs/tmdb-catalog.md](docs/tmdb-catalog.md).
Настройки открываются круглой кнопкой с шестерёнкой справа. Панель плавно
выдвигается справа на четверть ширины экрана поверх текущего раздела. В ней сначала
показаны категории: Phone Remote, TorrServer, Поиск, Метаданные, Воспроизведение,
Обновления, Оформление и О приложении. После выбора открывается только нужный
блок, и панель расширяется до половины экрана. BACK возвращает
к категориям с выделением прежней категории и затем закрывает панель;
фокус возвращается на шестерёнку. Кнопка со стрелкой ← также возвращает к категориям.
Во всех кнопках возврата стрелка центрирована внутри круглой кнопки;
для озвучивания сохранено название «Назад» / Back.
В каталоге доступны «Избранное» и «Смотреть позже». Удержание ОК на постере
открывает меню добавления или удаления из каждого списка. Короткое ОК открывает
карточку фильма. Списки сохраняются локально после перезапуска; очистка кеша
TMDB и медиатеки их не затрагивает.
Стрелки перемещают фокус между элементами настроек; LEFT не закрывает панель.
DOWN с любой кнопки верхнего меню переводит фокус в текущий экран, включая
открытую карточку фильма. Кнопки и поля адаптированы к ширине панели.
В «Оформление» есть тумблер «Анимации интерфейса»: изменение применяется сразу
и сохраняется после перезапуска. При включении подсветка кнопок меняется плавно,
текст и значки слегка увеличиваются при фокусе, а нажатие даёт короткий видимый
отклик даже при быстром клике. Бегунок переключателя двигается плавно. При
отключении анимаций состояния меняются сразу, подсветка фокуса остаётся видимой.
При входе в категорию сразу выделена кнопка «Назад». Мышь эмулятора и пульт
работают с теми же кнопками; после редактирования фокус возвращается на поле.
В шапке индикатор TorrServer: зелёный — работает, серый — недоступен,
красный — ошибка, жёлтый — запуск или остановка, включая перезапуск.
Карточка фильма показывает постер слева, название/описание и доступные год,
рейтинг, жанры и длительность справа. Кнопки редактирования данных и поиска
торрента с этой карточки удалены.

## Быстрая отправка на Mi Box из VS Code

Отладка и сопряжение выполняются один раз на приставке. После этого откройте
**корень репозитория** в VS Code и нажмите **⌘⇧B**. Задача
`Mi Box: Build & Deploy` автоматически подключается к сохранённому устройству,
определяет ABI, собирает Debug APK для него, устанавливает поверх существующей
версии и запускает приложение. Настройки и медиатека не очищаются.

Для Mi Box с 32-битным Android выбирается armeabi-v7a, для ARM64 — arm64-v8a.
Архитектура определяется системой, а не моделью процессора. APK содержит только
нужный ABI, сокращая передачу по Wi-Fi. Gradle daemon сохраняется между сборками.
Результаты и история задач Gradle каждой архитектуры хранятся отдельно в Library/Caches, рядом с
обычными сборками проекта, но не в каталоге Documents.

Другие задачи доступны через **Terminal → Run Task**:

- `Mi Box: Install Last Build` — отправить последний Debug APK без сборки.
- `Mi Box: Build & Deploy Preview` — собрать и отправить оптимизированный R8 Release.
- `Mi Box: App Logs` — логи только процесса приложения; Ctrl+C завершает просмотр.
  После переустановки запустите просмотр заново, поскольку PID изменится.

Из терминала:

```sh
./scripts/deploy-tv.sh
./scripts/deploy-tv.sh --no-build
./scripts/deploy-tv.sh --preview
./scripts/deploy-tv.sh --logs
./scripts/deploy-tv.sh --device IP:PORT
```

Адрес хранится локально в `.tools/tv-device` и не попадает в Git. Его можно
переопределить `TV_SERIAL` или `--device`. Если адреса нет, скрипт выберет ровно
одно подключённое физическое устройство; эмулятор автоматически не выбирается.
При смене IP задайте новый адрес; если ADB требует разрешения, подтвердите его
на телевизоре. Данные при ошибке подписи или версии автоматически не удаляются.
Остановите воспроизведение перед отправкой сборки: установка перезапускает приложение.

Проверено на MiTV-AFKR0 / Android 14 / armeabi-v7a: первая отправка — 41 секунду,
повторная без изменения кода — 18 секунд, из них сборка заняла 668 ms.
Это измерения одной сети, не обещание фиксированного времени; первая сборка
после изменения зависимостей или Preview/R8 дольше.

Документация: https://developer.android.com/tools/adb и
https://code.visualstudio.com/docs/debugtest/tasks.

## Android Studio и SDK на Mac

1. Установите стабильную [Android Studio для Apple Silicon](https://developer.android.com/studio).
2. Откройте `android-tv/`, выберите JDK 17+ для Gradle и дождитесь синхронизации.
3. В SDK Manager установите Android SDK Platform **37.0**, Build Tools **36.0.0**,
   Platform Tools и Android Emulator.
4. Для TV-эмулятора: Device Manager → Create Virtual Device → TV / 1080p →
   Android TV API 36, **arm64-v8a**. x86-образ не подходит ARM64 APK.
5. Run configuration: модуль `app`, Activity `MainActivity`.

В текущем workspace инструменты установлены локально в `.tools/`; Android Studio
пока не устанавливалась. `scripts/build-local.sh` выбирает этот JDK и SDK, если
они существуют. Этот каталог исключён из Git и из архива исходников.
После удаления `.tools/` используйте Android Studio либо переменные JAVA_HOME и
ANDROID_HOME со своим SDK. `android-tv/local.properties` — локальный, не публикуемый файл.

Скрипт выбирает AVD `TorrFrame_TV_API36`, а при его отсутствии использует уже
созданный `TorrServe_TV_API36`, сохраняя данные устройства. Другой AVD можно
указать через `TORRFRAME_AVD`. Запуск с видимым окном:

```sh
scripts/emulator.sh
# Запуск без окна для функциональных тестов:
scripts/emulator.sh -no-window -no-audio -no-snapshot
```

Если эмулятор уже работает, второй экземпляр этого же AVD не запускайте.
В профиле AVD включите аппаратную клавиатуру (`hw.keyboard=yes`). В окне эмулятора
стрелки перемещают фокус, Enter выбирает, Escape возвращает назад. Альтернатива:
Extended Controls → Directional Pad.
На этом Mac графический эмулятор установлен в `~/Library/Android/torrframe/`:
Qt не находил плагины при запуске из пути workspace с пробелами.
Для Jackett на этом же Mac используйте `http://10.0.2.2:9117` (или свой порт).
При разработке все визуальные проверки выполняет пользователь. Computer Use в
первой реализации не использовался; тесты и измерения выполнялись через CLI/ADB.

На macOS результаты сборки находятся в
`~/Library/Caches/TorrFrameAndroidTV/build/app/`, а не в `android-tv/app/build/`.
Это предотвращает дублирование изменяемых файлов сборки в синхронизируемом Documents.
Путь можно переопределить параметром `-PtorrframeBuildRoot=/absolute/path`.

## Сборка

Зафиксированы AGP 9.4.1, Gradle 9.6.0, Kotlin/Compose compiler 2.4.21,
Compose BOM 2026.09.00, TV Material 1.1.0, Media3 1.11.1, OkHttp 5.5.0 и Coil 3.6.3.
Совместимость подтверждена локальными сборками и тестами.
Wrapper проверяет SHA-256 Gradle, preBuild — SHA-256 встроенного TorrServer.

```sh
scripts/build-local.sh :app:assembleDebug
scripts/build-local.sh :app:testDebugUnitTest :app:lintDebug
# Подписанный локальным debug-ключом оптимизированный preview:
scripts/build-local.sh -PpreviewSigning=true :app:assembleRelease
# Без previewSigning: unsigned release, для отдельной production-подписи:
scripts/build-local.sh :app:assembleRelease
```

Результаты: `android-tv/app/build/outputs/apk/debug/` и `.../release/`.
Production-ключ следует создать и хранить вне репозитория, а готовый unsigned APK
подписать через Android SDK apksigner. Сохраните один production-сертификат для
всех будущих обновлений. Пароли и keystore не следует добавлять в Git.
Неподписанный release APK установить нельзя.

## Настройка Jackett

Settings → Search · Jackett:

- URL, например `http://192.168.1.100:9117` или HTTPS-адрес вашего reverse proxy.
- API Key из Jackett.
- Test Connection проверяет настоящий Torznab `t=caps`.
- Параметры сохраняются автоматически после изменения. API-ключ зашифрован AES-GCM с Android Keystore.

`127.0.0.1` на телевизоре означает сам телевизор. Автоматического адреса Jackett
нет. Поддерживаются базовые пути reverse proxy, стандартная проверка TLS и LAN HTTP.
API-ключи и URL с токенами не выводятся в пользовательские ошибки или Logcat.

Поиск выполняется по подтверждению пользователя, отменяет предыдущий запрос и
показывает не больше 200 результатов. Фильтры All / Movies / TV Shows, сортировка
Seeds / Size / Date. Используется `t=search`; фильтры используют категории
Torznab, без предположения о поддержке t=movie/t=tvsearch всеми индексаторами.
Поддерживаются magnet, перенаправление HTTP на magnet и скачивание torrent-файлов
на клиенте с последующей передачей байтов TorrServer.

Add to Library сохраняет раздачу. Watch добавляет её, получает видеофайлы и
запускает единственный файл либо предлагает выбор. Запись определяется hash,
разные релизы с одинаковым названием не объединяются.

## Метаданные

Settings → Metadata показывает порядок источников. По умолчанию:
**OMDB → TMDB → Кинопоиск**. Кнопки Move up / Move down меняют приоритет;
Порядок автоматически сохраняется между запусками. Первый уверенный результат завершает поиск.
Если совпадение не найдено, источник недоступен или детали не получены, поиск
продолжается в следующем источнике. После смены порядка Refresh Metadata
на странице фильма обновляет уже сохранённую карточку; массовое обновление
существующей медиатеки автоматически не запускается.

Ручного ввода ключей метаданных нет. Три ключа встраиваются в APK при сборке.
Для разработки скопируйте `android-tv/metadata-keys.properties.example` в
`android-tv/metadata-keys.properties` и заполните локальный файл, исключённый из Git.
В CI можно задать TORRFRAME_TMDB_API_KEY, TORRFRAME_OMDB_API_KEY,
TORRFRAME_KINOPOISK_API_KEY. Сборка без ключей завершается понятной ошибкой.
Ключи технически извлекаемы из APK, поэтому их нельзя считать секретами клиента;
исходники GitHub и архив исходников значений ключей не содержат.

AniList включается отдельной кнопкой для аниме и проверяется перед общей цепочкой,
как в macOS. По умолчанию выключен; старый выбор AniList сохраняется при миграции.
Язык метаданных en-US / ru-RU независим от языка интерфейса en / ru.
Ключ Jackett по-прежнему вводится для пользовательского сервера поиска и хранится
в Android Keystore. Старые ручные ключи метаданных удаляются при первом запуске
новой версии, настройки Jackett и медиатека сохраняются.

Алгоритм очищает названия релизов, определяет год/сезон/эпизод, создаёт ограниченное
число русских и английских вариантов, ранжирует совпадения и отбрасывает слабые.
Кеш: 30 дней найденные данные, 24 часа отсутствие результата; сетевые ошибки
не сохраняются как промахи. Постеры TMDB w342, backdrop w780. Файловый кеш изображений
ограничен 128 MiB, память Coil — 24 MiB.

При недоступности источников метаданных торренты всё равно добавляются и воспроизводятся.
Сохранённые метаданные остаются доступными без интернета. Refresh Metadata на
странице фильма принудительно повторяет разрешение названия.

## Плеер и пульт

UP / DOWN / LEFT / RIGHT перемещают фокус, OK выбирает действие, BACK возвращается
назад. Ввод — через системную клавиатуру, открывающуюся при выборе поля.
Скролл сохраняется в разделах; возврат из карточки восстанавливает выбранный постер.

В плеере OK показывает управление. При скрытых элементах LEFT / RIGHT перематывают;
при открытых управляют панелью. Настройки плеера позволяют выбирать доступные
аудиодорожки и субтитры. BACK останавливает текущий просмотр и возвращает на карточку.
При сворачивании приложения воспроизведение продолжается через MediaSessionService.
Позиция сохраняется при паузе/остановке и раз в 30 секунд.

Поддержка конкретных кодеков, HDR и многоканального звука зависит от устройства.
Аппаратное декодирование на физической приставке не проверено. Эмуляторный тест
использует собственный короткий H.264 ролик, не доказывает поддержку всех форматов.

## Phone Remote

Опциональная локальная веб-панель для телефона: «Настройки» → Phone Remote →
включить → открыть окно подключения. Телефон и TV должны находиться в одной доверенной LAN.
Можно сканировать QR либо открыть показанный адрес в браузере и ввести шестизначный
код с TV. Код и ссылка одноразовые, действуют две минуты; успешное подключение
погашает оба. «Новый QR-код и код» выдаёт новое приглашение.
По умолчанию модуль выключен; поиск, медиатека, настройки и плеер TV работают
без него. Подключение требует одноразового сопряжения, устройства можно отозвать.
HTTP в локальной сети не шифруется. Инструкция, архитектура, проверки и ограничения:
[docs/phone-remote.md](docs/phone-remote.md).

Для сборки APK теперь также нужны Node.js 20.19+ (или 22.12+) и npm: Gradle
автоматически собирает статический React/TypeScript WebUI в assets. На TV Node.js
не требуется; CDN и облачного backend нет.

## Обновления приложения и TorrServer

Check TorrServer проверяет официальные GitHub Releases. Встроенный ELF меняется
только с новой версией APK; скачивание и запуск ELF из записываемого каталога
приложения не используются.

Для Check App задайте в Settings репозиторий Android TV в формате owner/repository
и сохраните его. Публичный репозиторий и релиз этим запуском не создавались.
Нужен GitHub Release с одним universal APK (ARM64 + ARMv7) и GitHub SHA-256 digest для asset.
Проверяются checksum, applicationId, увеличение versionCode и сертификат подписи.
Install Update открывает стандартный Android Package Installer; при необходимости
сначала настройки разрешения установки из этого источника. Тихой установки нет.
Смена сертификата и rollback к меньшему versionCode отклоняются.

## Проверки

```sh
scripts/build-local.sh :app:testDebugUnitTest :app:lintDebug
# При работающем ARM64 TV AVD, Xcode command line tools, Python 3 и Go 1.27+:
scripts/run-native-tests.sh
```

Go нужен **только для тестового BitTorrent-сида на Mac**, в приложение он не добавлен.
Скрипт создаёт собственное видео, torrent, локальный tracker/seed на 127.0.0.1:
18765/18766, выполняет instrumentation и останавливает оба тестовых процесса.
В APK production нет тестового видео, fake API, MockWebServer или тестовых ключей.

Подтверждены: 25 JVM-тестов, 4 instrumentation-теста Android TV API 36, lint без
ошибок, Debug и оптимизированная Release-сборка. Полный результат и ограничения:
[docs/verification.md](docs/verification.md).

## Измерения

```sh
scripts/profile-adb.sh
.tools/sdk/platform-tools/adb logcat -s TorrFrameTiming:I AndroidRuntime:E
.tools/sdk/platform-tools/adb shell dumpsys gfxinfo tv.torrframe framestats
```

Профилировщик сохраняет отдельно startup, память приложения и TorrServer, кадры.
Debug Logcat содержит только фиксированные названия метрик и длительность:
activity_ui, server_start, library_load, search_results, playback_first_frame.
FrameMonitor считает кадры выше бюджета текущей частоты экрана. Для плотных
библиотек и реальных результатов Jackett нужно отдельно измерить прокрутку.
Цели <2 s / <500 ms / 60 FPS не гарантируются измерением одного эмулятора.
