# Настройки TorrServer для Android TV

Реализация выполнена поверх исходного проекта `df1a4c1`: Kotlin, Compose for TV,
OkHttp, ViewModel/StateFlow, существующее асинхронное хранилище SharedPreferences.
Новые зависимости не добавлены. Приложение содержит исполняемый TorrServer
MatriX.146.1 в `jniLibs` для ARM64 и ARMv7; сервер запускается из каталога nativeLibraryDir.

## Добавленные возможности

### Дополнение 0.1.7: веб-интерфейс в локальной сети

Встроенный сервер по умолчанию слушает `0.0.0.0`, поэтому обычный веб-интерфейс
доступен по `http://IP_ПРИСТАВКИ:ПОРТ` с других устройств в той же сети. В разделе
TorrServer показывается актуальный IPv4-адрес Wi-Fi/Ethernet; смена IP или порта
обновляет URL автоматически. Включать Phone Remote или настраивать ADB не нужно.

Приложение и Media3 используют прежний локальный адрес и тот же единственный
процесс. Переключатель «Доступ из локальной сети» сохраняется; выключение возвращает
прослушивание `127.0.0.1`. Изменение режима перезапускает процесс с сохранением
библиотеки и настроек движка, блокируется при активном воспроизведении приложения.
При возвращении в приложение библиотека синхронизируется с TorrServer.

Сетевая служба работает после Home/Back независимо от флага автозапуска. Этот флаг
по-прежнему определяет запуск после загрузки приставки. Когда отключены и LAN,
и автозапуск, сохраняется прежняя остановка по таймеру простоя. Принудительная
остановка приложения или завершение службы системой прекращает доступ к серверу.

### Исходное расширение настроек

- Сохранение HTTP/HTTPS-адреса, проверка URL и ответа TorrServer, восстановление
  `http://localhost:8090`, автоматическое подключение к новому адресу. Поддерживаются
  базовые пути reverse proxy. Авторизация TorrServer не добавлена.
- Явный выбор встроенного или внешнего сервера. Внешним может быть и отдельный
  процесс на localhost: выключение режима встроенного сервера убирает управление
  процессом, сохраняя адрес подключения.
- Состояния подключения, версия, периодическая проверка при открытом приложении,
  отдельная ручная проверка, объяснение ошибок и таймаутов.
- Реальный тест: время полного ответа `/echo`, загрузка 8 МиБ с `/download/8`,
  средняя скорость HTTP-запроса в Мбит/с. Неполный ответ, таймаут или отсутствие
  тестового endpoint не выдаются за измеренную скорость. Для localhost это
  соединение внутри устройства, а не скорость интернет-канала или торрента.
- Отдельный экран движка: кеш, буфер чтения вперёд, предзагрузка, лимиты загрузки
  и отдачи, число соединений, таймаут отключения торрента, порт пиров, режим
  ретрекеров, адаптивное чтение, шифрование BitTorrent, IPv6, TCP/uTP, UPnP,
  DHT, PEX, отдача и LPD. Показаны только поля подходящего типа, реально
  полученные от выбранного сервера.
- Сохранение изменённых полей поверх свежего ответа сервера: остальные поля,
  включая неизвестные приложению, сохраняются. После записи значения повторно
  читаются и сравниваются. Ошибка HTTP или отказ базы в сохранении показываются
  пользователю. Сброс через `def` доступен для подтверждённой версии MatriX.146.1
  и проверяет все отображаемые значения по умолчанию.
- Запуск, остановка, перезапуск, версия и ошибки встроенного процесса. Запуск
  сериализован mutex; смена адреса и остановка прежнего процесса выполняются
  под тем же mutex. Сохранены проверка занятого порта и безопасное восстановление
  собственного оставшегося процесса по PID, UID и командной строке.
- Автозапуск: BOOT_COMPLETED и foreground service. На Android 14+ используется
  поддерживаемый тип `specialUse` с объявленным назначением службы. Служба
  владеет локальным сервером и предотвращает обычную остановку по таймеру простоя.
  Несколько команд запуска используют один Service и один ServerController.
  Ошибка фонового запуска отображается отдельно от состояния самого процесса.
- Русские строковые ресурсы, TV-переключатели, редактирование через существующий
  диалог и системную клавиатуру, видимый фокус. Кнопки операций сохраняют фокус
  во время загрузки. Back возвращает из экрана движка к выбранной кнопке;
  сохранены позиция прокрутки и исходная навигация приложения.

Настройки подключения и автозапуска сохраняются сразу. Настройки поиска,
метаданных, воспроизведения и оформления используют прежнюю кнопку «Сохранить».
Параметры движка сохраняются отдельной кнопкой на сервере. Изменения подключения
не стирают несохранённые настройки поиска и не требуют повторного сохранения URL
общей кнопкой.

Миграция сохраняет прежний локальный порт, размер кеша, библиотеку, параметры
воспроизведения и зашифрованный ключ Jackett. Для старых установок URL выводится
из сохранённого порта. Первичная настройка кеша и отключение фонового обнаружения
выполняются один раз; при следующих запусках параметры движка не перезаписываются.

## Используемые API и источники

Проверены исходники официального тега
[MatriX.146.1](https://github.com/YouROK/TorrServer/tree/MatriX.146.1)
(commit `f4ce2d7986ae320176139314923280599d2614e6`):

| API | Назначение | Подтверждающий файл |
| --- | --- | --- |
| `GET /echo` | Доступность и версия | `server/web/server.go` |
| `POST /settings`, `{"action":"get"}` | Чтение параметров | `server/web/api/settings.go` |
| `POST /settings`, `{"action":"set","sets":{…}}` | Сохранение параметров | `server/web/api/settings.go` |
| `POST /settings`, `{"action":"def"}` | Сброс параметров | `server/web/api/settings.go` |
| `GET /download/8` | Реальный тестовый файл 8 МиБ | `server/web/api/download.go` |

Имена, типы, ограничения и значения по умолчанию проверены в
`server/settings/btsets.go`; поведение пересоздания движка — в
`server/torr/apihelper.go`; единицы лимитов скорости — в `server/torr/btserver.go`.
Существующие `/torrents`, `/torrent/upload` и `/stream` продолжают использоваться,
теперь с выбранным адресом сервера. `/shutdown` не используется: приложение
останавливает только собственный локальный процесс.

## Ограничения

Только для встроенного сервера доступны управление процессом, локальный HTTP-порт
и автозапуск. Для внешнего сервера доступны подключение, диагностика и поддерживаемые
параметры API. Локальная библиотека при смене сервера сохраняется; раздача должна
существовать на выбранном сервере, чтобы её можно было воспроизвести.

Root-запуск не реализован: в проекте нет поддерживаемого механизма запуска и
контроля root-процесса. Серверу root не нужен; фиктивный переключатель и запрос
`su` не добавлены. Не добавлены дисковые пути, сертификаты, логины или пароли.

Сохранение и сброс пересоздают Torrent-движок и сбрасывают активные раздачи,
включая раздачи других клиентов. Интерфейс требует подтверждения и блокирует
операцию во время собственного воспроизведения. Изменение кеша встроенного сервера
также обновляет сохраняемый бюджет памяти; для изменения GOMEMLIMIT нужен полный
перезапуск процесса, о чём сообщается в интерфейсе.

Приложение нельзя принудительно остановить и одновременно ожидать BOOT_COMPLETED:
после force-stop Android блокирует автозапуск до следующего открытия приложения.
Нужен хотя бы один запуск после установки. Ограничения производителя могут
потребовать разрешить работу в фоне. Запрет фонового запуска обрабатывается без
обходов системы. На Android 13+ при запрещённых уведомлениях служба видна в
системном списке активных приложений. После завершения службы системой не применяется
бесконечный цикл перезапусков.

## Проверки

Команда итоговой проверки:

```sh
cd android-tv
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:compileDebugAndroidTestKotlin
```

В этой среде установлены JDK 21, Android SDK Platform 37.0 и Build Tools 36.0.0.
Gradle 9.6.0 проверен по SHA-256 из wrapper. Для доступа через прокси использованы
локальные параметры Gradle и системное хранилище доверенных сертификатов;
конфигурация репозитория не менялась.

Сборке нужны уже предусмотренные проектом ключи TMDB/OMDb/Кинопоиска. В среде их
нет: проверочная debug-сборка использует значения `build-verification-only`
исключительно через переменные окружения. Эти значения не записаны в исходники.
Для APK, предназначенного для обычного использования, задайте собственные рабочие
ключи через `metadata-keys.properties` или существующие переменные окружения.
Реальные запросы к поставщикам метаданных с этими проверочными значениями не проверялись.

- Debug-сборка и компиляция Android instrumentation-тестов — успешны.
- Все 47 JVM-тестов проходят, в том числе 13 новых тестов настроек и сети.
- Lint: 0 ошибок, 20 предупреждений; существующие предупреждения не скрывались
  baseline или подавлением проверок.
- Дополнительно запущен официальный Linux-бинарник MatriX.146.1, проверенный по
  опубликованному GitHub SHA-256: `/echo`, чтение/запись с сохранением остальных
  полей, `/download/8` с точным размером 8 388 608 байт и `def` с повторным чтением
  значений по умолчанию прошли проверку. Тестовый процесс остановлен.
- Новые instrumentation-тесты проверяют сохранение/миграцию настроек, параллельные
  обновления, сохранность параметров движка после перезапуска, единственность
  процесса, ввод ошибочного URL и возврат фокуса из диалога и экрана движка.
  Они скомпилированы, но не запускались: Android TV/ARM-устройство не подключено.

На реальном Android TV следует проверить весь путь с пультом, системную клавиатуру,
Back из диалогов, восстановление фокуса и прокрутки, воспроизведение через локальный
и внешний сервер, сохранение после закрытия приложения, загрузку приставки с
включённым/выключенным автозапуском, отсутствие второго процесса, уведомление и
ограничения фоновой работы на прошивке устройства. Отдельно проверить отказ в
доступе, отключение сети, неверный адрес и изменение параметров без активного просмотра.
