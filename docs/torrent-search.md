# Локальный TorrentSearch для Android TV

## Источник и лицензии

Поисковые провайдеры адаптированы из [prajwalch/TorrentSearch](https://github.com/prajwalch/TorrentSearch), commit `661c5adf3493add41ed2a6bda422b22d8aa73533`. Его [MIT-лицензия](https://github.com/prajwalch/TorrentSearch/blob/661c5adf3493add41ed2a6bda422b22d8aa73533/LICENSE) разрешает использование, изменение и распространение при сохранении copyright и текста лицензии. Полный текст включён в модуль и APK, доступен в существующем окне лицензий. Изменения перечислены в `android-tv/torrent-search/THIRD_PARTY_NOTICES.md`.

HTML разбирается jsoup 1.23.2 (MIT); его лицензия также включена в APK. Для поддержки jsoup на Android используется NIO desugaring. HTTP-клиент и coroutines уже существовали в приложении. UI, Ktor, Koin, хранение данных, аккаунты и браузер для обхода защит из чужого приложения не перенесены. Лицензия исходного кода не гарантирует доступность сторонних сайтов и не отменяет их собственные условия доступа.

## Структура

- `:torrent-search` — независимый Kotlin/JVM-модуль: модели, провайдеры, агрегация. От Android, TorrServer, TMDB, Jackett и UI он не зависит. HTTP-транспорт внедряется через `SearchTransport`; Android предоставляет `org.json`.
- `features/torrentsearch/data` — адаптер существующего `Http`, получение выбранного torrent-файла и мост к `LibraryRepository`.
- `features/torrentsearch/presentation` — ViewModel и Compose for TV. Отдельная страница открывается из подробной карточки каталога или медиатеки.

Адаптированы Rutor, NoNameClub, TorrentsCSV, Knaben, ThePirateBay, YTS (фильмы), Nyaa, 1337x и EZTV (сериалы). Сохранены запросы/формы/селекторы исходных провайдеров; Nyaa ограничен видеокатегорией anime, PirateBay — общей видеокатегорией, чтобы сохранять HD/UHD. Провайдеры только для книг, игр, музыки и adult не относятся к этой функции.

## Поведение

Запросы используют оригинальное название с годом и локализованное название с годом, если они различаются. Для сериала дополнительно используется оригинальное название без года: раздачи отдельных сезонов часто не содержат год премьеры. Повторяющиеся запросы исключаются.

Одновременно работают до четырёх источников. Тайм-аут каждого — 18 секунд, включая его варианты запросов. Каждая полученная партия сразу появляется на экране. Ошибка/тайм-аут одного источника сохраняет уже полученные результаты и не прерывает остальные. Выход и повторный поиск отменяют предыдущие запросы.

После каждой партии список сортируется по убыванию сидов. Неизвестное число идёт после известных, включая ноль. При равенстве сортировка стабильна по названию и ключу. Дубликаты magnet с одним canonical info-hash объединяются, в том числе hex/base32 и URL-encoded btih; числа сидов/пиров берутся по максимуму, не суммируются. Для раздач без доступного hash ключом служит URL и провайдер: гарантировать объединение таких раздач между сайтами без дополнительных запросов нельзя. Список ограничен 1500 наиболее востребованными результатами.

Показываются название, сиды, пиры, размер, источник и найденные в имени признаки качества/формата. Неизвестные поля обозначаются «—». Источники имеют независимые статусы. Фокус привязан к ключу раздачи, поэтому поздняя вставка сверху не переключает выбор на другой торрент. Есть повтор поиска, возврат, меню добавления/просмотра и выбор файла при нескольких видео. После возврата фокус восстанавливается на кнопке TorrentSearch.

Magnet для 1337x и NoNameClub разрешается только после выбора результата. Torrent-файлы также скачиваются только после выбора; ограничены размер тела и число перенаправлений. Защита/страница авторизации, HTML вместо torrent и недоступная magnet-ссылка дают ошибку, без браузера и обхода защиты.

Добавление использует общий импорт `LibraryRepository.add(TorrentPayload, title, hash)`. Старый `add(SearchResult)` для Jackett вызывает тот же импорт с прежним загрузчиком. Файлы, resume/выбор видео, stream URL и PlayerActivity используются существующие. Для «Смотреть» торрент сначала добавляется; если видео пока недоступно, он остаётся в медиатеке, а интерфейс объясняет ошибку.

Результаты поиска хранятся только в ViewModel: повтор обновляет текущие сведения о сидах. Кеширование TMDB/постеров и отдельный язык метаданных не менялись.

## Проверка

`EngineTests` и `ProviderTests` покрывают все девять адаптеров, поля, запросы, ленивое разрешение magnet, последовательные ошибки, тайм-ауты, отмену, постепенную выдачу, сортировку, дедупликацию, лимит, варианты названий и качество.

`TorrentSearchViewModelTests` проверяют add/watch, resume и выбор видео, ошибки импорта/файлов, отмену устаревшего действия и восстановление маршрута. `TorrentSearchNetworkTests` проверяют скачивание, относительные и magnet-перенаправления, ошибочный HTML и циклы.

`TorrentSearchNavigationTest` проверяет D-pad, сохранение фокуса при поздних ответах, меню и повтор, файл сериала, масштабы/темы, реальную кнопку в карточке TMDB и возврат к ней. `TorrentSearchIntegrationTest` проверяет прямые запросы с Android для фильма и сериала, сортировку каждой партии, импорт локального тестового torrent и magnet через настоящий TorrServer. `NativeIntegrationTest#packagedExecutableApiPersistenceAndPlayback` проверяет существующий плеер на созданном нами видео, сохранение прогресса и воспроизведение в фоне.

Для native fixture-тестов предварительно запустить существующие `scripts/test-fixture/tracker.py` и fixture seeder из `scripts/run-native-tests.sh`.

Основные команды:

```sh
scripts/build-local.sh :torrent-search:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
scripts/build-local.sh :app:connectedDebugAndroidTest -PtorrframeAbi=arm64-v8a -Pandroid.testInstrumentationRunnerArguments.class=tv.torrframe.TorrentSearchNavigationTest
scripts/build-local.sh :app:connectedDebugAndroidTest -PtorrframeAbi=arm64-v8a -Pandroid.testInstrumentationRunnerArguments.class=tv.torrframe.TorrentSearchIntegrationTest
```

Живая проверка 15 октября 2026 на Android TV API36: Interstellar — 226 уникальных результатов, Breaking Bad — 245. Результаты дали Rutor, NoNameClub (для сериала), TorrentsCSV, Knaben, ThePirateBay и YTS (для фильма). Nyaa вернул пустую выдачу. 1337x и EZTV были недоступны; их сбои не мешали поиску. Эти цифры зависят от сети, запроса и состояния источников; работу всех сайтов постоянно гарантировать нельзя. Автоматические отчёты и лог живой выдачи сохраняются в `artifacts/torrentsearch/`.

Итог доступных проверок: 130 unit-тестов (112 приложения + 18 модуля) и 54 уникальных Android-теста прошли, `lintDebug` завершился без ошибок и без замечаний к новой функции. Универсальный debug APK содержит ARM64 и ARMv7; подпись, обе закреплённые контрольные суммы TorrServer и включённые лицензии проверены. APK установлен и MainActivity запущена на эмуляторе. Визуальная проверка человеком не выполнялась.

## Настройки TorrentSearch

Отдельная категория в правой панели настроек содержит:

- Включение каждого из девяти источников, команды «Включить все» и «Отключить все». Пустой список сохраняется как отключённый поиск, а не как значения по умолчанию.
- Несколько разрешений (480p/720p/1080p/2160p) и форматов (WEB-DL/WEBRip/BluRay/BDRip/HDTV/DVD); пустой выбор означает любое значение. Внутри группы действует OR, между группами и остальными фильтрами — AND.
- Минимальный и максимальный размер с шагом 0,5 ГиБ, до 1024 ГиБ; максимум 0 означает отсутствие верхней границы. Числовой размер имеет приоритет, строковые размеры источников также разбираются: GiB/MiB — двоичные, GB/MB и ГБ/МБ — десятичные единицы.
- Минимум сидов 0–10000 и отдельное скрытие раздач с известными 0 сидов. При минимуме больше 0 неизвестное число также не подходит. Если активен фильтр размера/качества, неизвестное соответствующее значение не проходит фильтр.
- Ожидание одного источника от 5 до 60 секунд (по умолчанию 18).
- Название для поиска: оригинальное, русское либо оба. Для карточек TMDB русский вариант берётся из существующего `CatalogRepository` и его языкового кеша, независимо от языка интерфейса. При отсутствии данных, ошибке или превышении 5 секунд используется доступное название. Для медиатеки с другим поставщиком метаданных используется доступное название. Оригинальное название сохраняется; год и варианты сериала без года учитываются в выбранных языках.
- Сброс только параметров TorrentSearch к значениям по умолчанию.

Параметры хранятся в существующем `SettingsStore` как отдельное поле. Кодек различает отсутствующий и пустой список источников, восстанавливает безопасные значения при повреждённых данных. `SettingsMerge` сохраняет независимые ожидающие изменения отдельных параметров. Автосохранение использует существующий `SettingsViewModel.edit`, без новых баз, зависимостей, ключей и серверов.

Снимок настроек применяется при запуске или «Повторить». Изменение каждого переключателя не перезапускает текущие сетевые запросы. Отключённые/неподходящие для фильма или сериала источники не вызываются; если активных источников нет, дополнительный запрос русского названия также не выполняется. Фильтрация идёт после объединения hash-дубликатов, порядок по сидам сохраняется после каждой партии. Пустая выдача и отключённые источники имеют отдельные пояснения.

Проверки настроек: `OptionsTests`, `TorrentSearchSettingsTests`, дополнительный сценарий `TorrentSearchViewModelTests`, а также `TorrentSearchSettingsNavigationTest` (автосохранение/перезагрузка, D-pad, границы счётчиков, оба масштаба/темы, русский запрос при английском интерфейсе и подключение сохранённой политики к реальному маршруту каталога).


## Jackett on TV

Catalog and TorrServe-library detail cards open the same results screen with a
separate Jackett provider engine. The selected backend survives Retry and saved
state restoration, and does not enable built-in providers when Jackett is selected.
Shared sorting, quality/size/seed filters, import, file selection and playback are
retained. Jackett private download URLs use `JackettClient.download`, preserving
magnet redirects and torrent-file downloads before the normal TorrServe import.
The enabled flag is shared with Phone Remote. Missing configuration opens the
Jackett settings panel; Back restores the invoking search button.
