# Phone Remote

Phone Remote — дополнительный локальный интерфейс TorrFrame. При первой установке включён; сохранённый выбор пользователя сохраняется при обновлении.
Основные экраны TV, поиск, SQLite-медиатека, настройки, встроенный TorrServer и
Media3-плеер работают независимо от него. Модуль не запускается из BOOT_COMPLETED.

## Подключение

1. Откройте приложение на TV, затем «Настройки» → Phone Remote.
2. Включите модуль. По умолчанию используется порт 8765; можно выбрать другой
   свободный порт, отличный от HTTP-порта TorrServer.
3. Дождитесь состояния «Работает» и откройте QR-код. Также доступна компактная
   кнопка телефона в верхней панели, когда модуль включён.
4. Телефон и телевизор должны находиться в одной доверенной локальной сети.
   Сканируйте QR и откройте ссылку в браузере в течение двух минут. Если камеры нет,
   откройте показанный адрес вручную и введите шестизначный код с экрана TV.
5. Сессия сохраняется в браузере на семь дней. Можно повторно открыть показанный
   локальный адрес. Авторизацию устройства можно отозвать на TV.

Отключение модуля закрывает HTTP/WS, отменяет его задачи, удаляет сессии и
освобождает порт. Медиатека, история, метаданные и основные настройки сохраняются.
После включения снова потребуется QR или новый код. При смене IP откройте обновлённый адрес на TV;
cookie привязана браузером к прежнему IP, поэтому может потребоваться новое сопряжение.

## Реализованные возможности

- Мобильный dark WebUI: главная, поиск, медиатека, пульт, настройки. Используется
  существующая иконка приложения; внешние CDN, шрифты и frontend-сервер не нужны.
- Реальный поиск Jackett с теми же настройками и фильтрами, добавление раздачи,
  синхронизация с TorrServer, карточки, удаление, выбор видеофайла и запуск на TV.
- Общие метаданные: переименование, повторное получение, сброс, поиск и ручной выбор
  OMDb/TMDB/Kinopoisk/AniList; общий порядок источников. Эти операции также добавлены
  в карточку фильма на TV и работают при выключенном Phone Remote.
- Общие настройки поиска, языков, возобновления воспроизведения и обновлений.
  Существующий Jackett API key можно изменить; прочитать сохранённый ключ через
  удалённый API нельзя. Авторизация TorrServer не добавлена.
- TorrServer: локальный/удалённый адрес, состояние/версия, проверка соединения,
  диагностика, локальный запуск/остановка/перезапуск/автозапуск, чтение и изменение
  поддерживаемых параметров движка, восстановление defaults для MatriX.146.1.
  Повторно используется API и валидация из раздела настроек TorrServer.
- Проверка версии TorrServer, проверка/скачивание APK через существующий механизм
  обновлений с checksum, сертификатом, applicationId и versionCode. Установщик
  требует подтверждения на TV. Встроенный ELF обновляется только с APK.
- Прямое управление Media3: play/pause/stop, позиция, перемотка, доступные
  аудиодорожки/субтитры. Перед stop сохраняется позиция. Команды привязаны к identity
  текущего файла и не применяются к фильму, который уже сменился.
- HTTP-команды и WebSocket-события, автоматическое переподключение, актуальный
  snapshot после разрыва/смены процесса/пропуска события. Длительные операции имеют
  состояния, таймаут и отдельный результат. Опасные действия требуют подтверждения.

## Архитектура и файлы

Новые Android-компоненты находятся в
`android-tv/app/src/main/java/tv/torrframe/phoneRemote/`:

| Каталог | Ответственность |
| --- | --- |
| `server` | Ktor CIO, маршруты, assets, lifecycle manager, отдельный foreground service |
| `security` | одноразовое сопряжение, сессии, Host/Origin/CSRF и фильтр локальных адресов |
| `discovery` | адрес Wi-Fi/Ethernet и генерация QR через ZXing |
| `api` | whitelist DTO, общие команды, ограниченная очередь операций |
| `synchronization` | проекции общих Flow, версия/эпоха/номер событий |
| `settings` | только enabled/port модуля, асинхронное сохранение |
| `ui` | TV-секция, QR, список и отзыв устройств |

Frontend: `android-tv/phone-remote-web/` — React/TypeScript/Vite, страницы,
переиспользуемые компоненты, типизированный API и протокол событий. `branding.mjs`
копирует настоящую `app_icon.png` из Android-ресурсов. Gradle выполняет `npm ci`
и сборку assets перед сборкой APK. Для сборочной машины нужен Node.js 20.19+
или 22.12+ и npm; на приставке Node.js не используется. Генерируемые assets и
node_modules исключены из Git. Добавлены только Ktor CIO/WebSockets и ZXing;
тестовый Ktor host и UI-библиотека не подключены.

Новые общие компоненты вне модуля:

- `core/server/TorrServerActions.kt` — действия сервера для TV и API;
- `core/storage/SettingsMerge.kt` — сохранение изменений TV без перезаписи
  несвязанных обновлений с телефона;
- `features/metadata/MetadataEditor.kt`, `MetadataEditorDialog.kt` — общий редактор
  и его TV-интерфейс;
- `features/player/PlaybackCoordinator.kt`, `PlaybackSelection.kt` — прямые команды
  плеера и единые правила выбора видеофайла;
- `features/updates/UpdateManager.kt` — существующая логика обновлений, вынесенная
  из ViewModel без замены проверок безопасности.

Изменены `TorrFrameApplication`, `MainActivity`, manifest, Gradle, русские ресурсы,
`LibraryStore`, `SettingsStore`, `ServerController`, `LibraryRepository`,
`MetadataProviders`, экраны/ViewModel настроек и карточки, `PlaybackService`,
`PlayerActivity`, `UpdatesViewModel`, общие TV-компоненты и лицензии.
Полный список созданных и изменённых файлов: [phone-remote-files.txt](phone-remote-files.txt).
Для Release добавлены два точных `dontwarn` в `proguard-rules.pro`: только классы
`java.lang.management`, используемые необязательным desktop debug detector Ktor.
Этот детектор перехватывает отсутствие классов на Android и возвращает false;
глобального подавления предупреждений R8 нет.

Нет второй медиатеки или второго хранилища основных настроек. Все записи идут в
существующие repository/store. Настройки имеют persistent revision: устаревшая
удалённая запись отклоняется; TV сохраняет только свои изменённые поля. Engine save
сравнивает исходные значения изменяемых полей. Общие серверные операции
сериализованы; уже начавшаяся операция приложения завершается независимо от
отключения Phone Remote, а его ещё не начавшиеся задачи отменяются.
Поколения metadata lookup предотвращают запись устаревшего результата поверх
ручного выбора/переименования/сброса.

## Протокол

| Маршрут | Назначение |
| --- | --- |
| `GET /` и `/assets/...` | локальные статические файлы из APK |
| `POST /pair` | обмен одноразового QR-токена или шестизначного кода на браузерную сессию |
| `GET /api/state` | начальное общее состояние и CSRF текущей сессии |
| `POST /api/commands` | `{requestId, type, args}`, ответ 202 с operationId |
| `GET /api/operations/{id}` | результат только собственной операции |
| `POST /api/logout` | отзыв текущего устройства |
| `WS /api/events` | протокол `phone.v1`, CSRF во втором subprotocol |

Событие: `{v:1, epoch, sequence, type, data}`. Типы:
`library.updated`, `settings.updated`, `playback.updated`, `torrserver.updated`,
`updates.updated`, `operation.updated`; `sync.ready` запускает получение snapshot.
Изменение библиотеки передаёт сигнал revision, а не отдельную постоянную коллекцию
для каждого клиента. Позиция публикуется раз в секунду только при подписчиках и
активном плеере. Лёгкая проверка соединения раз в 15 секунд выполняется только при
подписчиках и свёрнутом TV UI. При выключенном модуле этих задач нет.

Повторный requestId текущей сессии возвращает ту же операцию в пределах ограниченной
очереди. Это не гарантия exactly-once после перезапуска процесса. Клиент не повторяет
неопределённо завершившееся разрушительное действие автоматически. Settings CAS и
engine base защищают от устаревших параллельных записей.

## Защита и жизненный цикл

Случайные 256-bit токены, QR содержит только одноразовый токен в URL fragment:
он не отправляется серверу в адресе HTTP-запроса. После обмена fragment удаляется.
Токен действителен две минуты, привязан к текущему origin, повторно не используется.
Альтернативный шестизначный код генерируется SecureRandom вместе с QR, хранится
только как SHA-256 в памяти и имеет тот же origin/срок. Успешный обмен любым способом
погашает оба варианта. Обновление окна выдаёт новое приглашение. Число проверок
кода ограничено восемью на приглашение суммарно для всех клиентов, дополнительно
действует существующий лимит по IP. Код доступен только в окне TV, не в snapshot.
Сессии имеют отдельные CSRF и сохраняются как SHA-256 fingerprints cookie;
сырой cookie не хранится на TV. Cookie: HttpOnly, SameSite=Strict, Path=/api.
При отзыве память очищается до записи preferences, чтобы ошибка диска не оставляла
действующую авторизацию в процессе. Отзыв закрывает WS и отменяет задачи устройства.

Проверяются точные Host и Origin. Управляющие POST и WS требуют CSRF. CORS отсутствует,
прокси-заголовки не доверяются; адреса клиентов проверяются по числовому remoteAddress.
Сервер привязан к частному IPv4 Wi-Fi/Ethernet, не к 0.0.0.0 или публичному интерфейсу.
Управляющие API требуют cookie. Есть CSP, запрет iframe, no-referrer/no-store,
ограничения body, времени чтения, попыток сопряжения, HTTP concurrency, WS и операций.
В событиях и snapshot нет API keys; download URL не принимается от клиента,
результаты поиска используются через краткоживущие session-scoped handles.
Токены, команды и их аргументы не пишутся в журналы.

Это обычный HTTP в доверенной LAN: трафик не зашифрован, HTTPS не реализован.
Локальный перехватчик может украсть передаваемый cookie. Не используйте недоверенную
Wi-Fi и не настраивайте проброс этого порта в интернет. Автоматического проброса нет.
Новые глобальные cleartext-разрешения не добавлены.

Сервис отдельный, user-enabled, foreground `specialUse`, START_NOT_STICKY.
Он переживает переходы между экранами/сворачивание, отслеживает IP и потерю LAN.
Ошибка запуска/занятый порт отображается в TV-секции; доступен повторный запуск.
При выключении освобождаются callbacks, engine, WS и coroutine scope. Быстрые
переключения защищены mutex и поколением runtime. TorrServer имеет собственный
жизненный цикл. После остановки Android/force-stop Phone Remote восстанавливается
при следующем открытии приложения; он не обходит фоновые ограничения Android.
Для публикации в Google Play необходимо проверить допуск specialUse FGS.

## Проверки

Добавлены JVM-тесты `PhoneRemoteSecurityTests`, `PhoneRemoteServerTests`,
`PhoneRemoteOperationTests` и четыре Android integration-теста
`PhoneRemoteIntegrationTest`. Серверные JVM-тесты открывают реальные CIO/OkHttp
сокеты: авторизация, Origin/Host/CSRF, one-time pairing, WS, отзыв, занятый порт,
освобождение порта и повторный запуск.

Android instrumentation здесь только компилируется: физического Android TV/ARM-эмулятора нет.

На устройстве необходимо проверить D-pad/Back/фокус диалогов, QR камерой,
сохранение сессии, отзыв, два телефона, Wi-Fi/Ethernet и смену DHCP IP, занятый порт,
быстрые переключения, фон/force-stop/перезапуск, реальные Jackett/metadata keys,
стандартный установщик и Media3 с настоящими дорожками/seek/history.
Особенно нужны Mi Box и iOS Safari; текущие браузерные проверки выполнены в Chromium.

## Ограничения и ещё не реализовано

- IPv6-only, mDNS и TLS не поддерживаются; используется доступный частный IPv4.
- Отдельного OTA-обновления TorrServer ELF, полного reset приложения и очистки
  torrent-буфера нет в исходном приложении: фиктивные команды не добавлены.
  Очистка существующего metadata cache поддерживается.
- Избранное/категории отсутствуют в исходной модели; WebUI их не имитирует.
  Имеющаяся история/позиция отображаются через общую библиотеку/плеер.
- Поиск возвращает реальные торренты Jackett. Постеры/метаданные в результатах
  доступны для уже сопоставленных записей медиатеки; массовое обогащение каждого
  нового результата поиска отдельно не добавлено.
- Добавление произвольного magnet из формы WebUI пока не предоставлено;
  добавление реальных результатов поиска работает.
- Для запуска нового фильма и Android Package Installer TV-приложение должно
  быть открыто; управление уже работающим плеером доступно в фоне.
- Сохранена существующая политика остановки локального TorrServer после ухода
  TV-приложения в фон без активного плеера/собственного foreground service сервера.
  Phone Remote сам по себе не удерживает процесс TorrServer. Для постоянной работы
  локального сервера используется его отдельная настройка автозапуска/сервис.
- Список медиатеки приходит полным snapshot; серверной пагинации нет.
  Производительность очень больших библиотек требует измерения на приставке.
- Phone settings, pairing и выдача новых разрешений доступны только на TV.
  Root и обход системных подтверждений не добавлены.

## Воспроизводимая проверка

С существующими metadata-ключами проекта и установленными JDK/Android SDK/Node.js:

```sh
cd android-tv
gradle :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest \
  :app:lintDebug :app:compileDebugAndroidTestKotlin
cd phone-remote-web
npm test
```

Для проверки сборки в этой среде настоящие ключи OMDb/TMDB/Kinopoisk были
недоступны. Вместо них **только через переменные окружения сборочного процесса**
переданы явно нерабочие значения `build-verification-only`. Они не добавлены
в исходники. Эти APK подтверждают компиляцию/упаковку, но не успешные запросы
к данным провайдерам. Для обычной сборки используйте свои прежние ключи через
`metadata-keys.properties` или существующие переменные окружения.

Chromium проверен на ширинах 360, 390, 430, 768, 1440 CSS px: все пять вкладок и
настройки сервера без горизонтального overflow и JavaScript errors. Использовались
только browser test fixtures вне production assets; это не проверка сети Android
или успешной работы metadata providers. JS bundle около 238 KB, CSS около 20 KB;
в APK также включена настоящая иконка 23 KB. Safari физически не запускался.

Результат текущей финальной проверки (12 октября 2026):

- `assembleDebug` и `assembleRelease` с R8/resource shrink — успешно.
  Release APK в этой среде unsigned; установка и запуск оптимизированного APK
  на устройстве не проверены.
- `testDebugUnitTest` — 63 теста, 0 failures/errors, включая 16 новых тестов
  Phone Remote и прежние проверки приложения/настроек TorrServer.
- `lintDebug` — 0 ошибок, 25 предупреждений.
- `compileDebugAndroidTestKotlin` — успешно; instrumentation не запускалась.
- `npm test` — 7 тестов протокола, 0 failures.
- APK содержит четыре WebUI asset-файла (HTML/JS/CSS/оригинальная иконка).
- Chromium smoke-проверки пяти ширин — успешно, с тестовыми данными.
- `git diff --check` и обратная проверка применения экспортируемых патчей — успешно.

Проверка на физическом Mi Box, Android TV и iOS Safari остаётся обязательной
перед выпуском. Приведённые результаты не заменяют приёмку на устройствах.
